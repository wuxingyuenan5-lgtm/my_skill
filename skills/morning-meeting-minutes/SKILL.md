# 晨会纪要整理（紧凑单页版）

## Overview

将晨会录音转录并提炼成一份单页紧凑的会议纪要 docx。**结构固定为单标题 + 4 节**，全部用项目符号/段落表达，**0 表格**。内容优先级：**大盘/夜盘/商品 → 核心讨论（法案、板块、资源）→ 基金经理观点与操作 → fof 子基金观察 → 后续任务**。

## When to Use

用户给出音频文件（m4a/mp3 等）和/或截图，要求整理/生成晨会纪要，且内容应控制在一页纸内。

## Workflow（精简流程，目标 10 分钟内完成）

### Step 1: 收集输入

1. 读取用户引用的音频路径；
2. 读取手记/截图（如有——**手记不是必需品**，没有也能独立完成）；
3. 文件名：`YYYY.MM.DD 会议纪要.docx`。

### Step 2: 转录音频（后台执行，不阻塞）

1. 收到音频后**立即启动后台转录**，不要再等：
   ```bash
   nohup python scripts/transcribe.py <音频> -o transcript.txt &
   ```
2. 告知用户当前进度（音频时长、预计 5-8 分钟），让用户知道在跑；
3. 脚本内置优化参数（**base 模型、beam_size=3**）——beam=1 虽快但数字/标的上错误率高，2026-08-14 用户明确要求保质量。

### Step 3: 转录完成后提取要点

1. **转录是唯一必选项**（手记如有则合并补充，没有也能独立完成）；
2. 用 `grep` 扫描关键板块/标的关键词定位片段，仅读取上下文 5-10 行；
3. 按 4 节结构归类：大盘/商品 → 核心讨论 → 基金经理观点 → 后续任务。

### Step 4: 提取核心要点（晨会结构引导）

晨会一般结构：**开头粗略聊市场概要和商品，随后基金经理重点讲个股、股票大盘以及操作和分析**。提取时按此展开，重点是前两者：

1. **市场概要 + 商品**（开头部分，要详细）：海外夜盘美股/PPI 等宏观数据、商品期货（金属/黄金/原油）、指数位置、美联储政策判断（如 2 年期国债收益率）；
2. **基金经理操作与仓位**（核心中的核心）：做多做空方向与点位、仓位结构（各板块占比 %）、加减仓/清仓动作、交易计划、账户差异；
3. **财报与个股**（基金经理后半段重点）：中报/季报超预期标的、两率/产能等细节、看好的个股与逻辑、估值空间；
4. **后市观点**：对指数/板块的判断、调整时间、下半年方向。

**用户明确要求：市场概要、基金经理的分析和操作"尽可能详细"，不要丢失信息质量**——宁可多写几句分析逻辑，也不要只留结论。整体仍控制在一页纸内，用分号/句号紧凑合并。

**关键规则：保留分析逻辑链，不只看结论。** 例如：
- ❌ "药明康德有 20 点空间"（只有结论）
- ✅ "药明康德明年业绩尚未上修，如果上修估值 16 倍→约有 20 点空间"（保留空间来源）

每段应包含"**是什么 → 为什么 → 怎么做**"三要素。但整体仍需控制在一页纸内——用分号/句号紧凑合并而非删除分析。

### Step 5: 生成 docx（一次性脚本完成）

使用 `scripts/generate_morning_minutes.py` 生成。**不要**在生成后用 `doc_get_document_content` 反复验证样式——直接用 python-docx 写好就保存。

**样式规范：**

- 字体：**宋体**（中文）+ Times New Roman（英文/数字）；
- 页面：上下边距 1.6cm，左右 2.0cm；
- 单标题：`YYYY.MM.DD 会议纪要`，15pt 深蓝 `#1F3864`，居中粗体（**只一个标题，不要"会议纪要"+"日期"两遍**）；
- 节标题：12pt 深蓝粗体，段前 8pt、段后 3pt；
- 子标题：11pt 深蓝粗体，段前 5pt、段后 2pt；
- 正文：10pt 黑色，1.25 倍行距，段前 1pt、段后 1pt；
- 段落缩进：0.3cm 起始；
- **不加粗整段正文**——只对关键标签/标的加粗（如"光模块："、"洛阳钼业"），其余正常字重。

**结构模板（4 节固定）：**

```
1. 一、大盘 / 夜盘 / 商品
2. 二、核心讨论
   2.1 法案进展与板块差异
   2.2 资源民族主义主线（如有）
   2.3 公司基金经理观点与操作策略
3. 三、观察的 fof 子基金（可吸取优点）
4. 四、后续任务
```

**段落合并规则：**同一子主题下的多条要点合并成 1 段，用分号/句号分隔，避免每个要点独占一行（节省版面）。

### Step 6: 交付

1. `present_files` 展示 docx；
2. 当日 memory 记一行：音频文件、纪要文件名；
3. 不必询问用户确认样式——按本 skill 默认即可。

## Efficiency Notes（重要）

- **转录：base 模型 + beam=3**——34 分钟音频约 5 分钟完成（6.7x 实时）；beam=1 虽更快但数字/标的上错误率高，已弃用（2026-08-14）；
- **失败快速暴露**：转录脚本 1-2 分钟内即报错——音量极低/无法识别语音时立即提示"重新录音或改用手记"，**绝不长时间空跑重试**；
- **不要读取截图**，除非用户明确说"参考截图内容"；
- **不要在生成后验证 docx**，直接交付；
- **不要重复写 memory**，每次只追加一行；
- **内容用 `grep` 扫描关键字**定位关键片段，仅读取 5-10 行上下文，不读全文件；
- 总目标：**10 分钟内完成**（转录 2-3 分钟 + 处理 3-5 分钟）。

## Scripts

- `scripts/generate_morning_minutes.py`：单页紧凑版纪要生成器。修改文件中的标题日期和四个章节的段落内容后运行即可。
