# 晨会纪要整理（紧凑单页版）

## Overview

将晨会录音转录并提炼成一份单页紧凑的会议纪要 docx。**结构固定为单标题 + 3 节**，全部用项目符号/段落表达，**0 表格**。内容按主题归位：**基金经理操作与仓位（核心）→ 市场概要 → 其他**。

## When to Use

用户给出音频文件（m4a/mp3 等）和/或截图，要求整理/生成晨会纪要，且内容应控制在一页纸内。

## Workflow（精简流程，目标 10 分钟内完成）

### Step 1: 收集输入

1. 读取用户引用的音频路径；
2. 读取手记/截图（如有——**手记不是必需品**，没有也能独立完成）；
3. **用户口头补充缺失内容**（2026-09-09 案例：录音没录到开头，用户口头补"A股高开低走/WTI 创新高/2Y 美债利率上升"）——并入纪要开头，单独标「昨日盘面（补充）」小节，与转录内容明确区分；
4. 文件名：`YYYY.MM.DD 会议纪要.docx`。

### Step 2: 转录音频（后台执行，不阻塞）

1. 收到音频后**立即启动后台转录**，不要再等（**默认 medium 模型，2026-09-02 定稿；批处理加速，2026-09-03 定稿**）：
   ```bash
   "C:/Users/ThinkPad/.workbuddy/binaries/python/envs/default/Scripts/python.exe" scripts/transcribe.py <音频> --model "C:/Users/ThinkPad/.workbuddy/models/faster-whisper-medium" -o transcript.txt
   ```
   脚本默认已启用 `BatchedInferencePipeline`（bs=8）+ `cpu_threads=8`，无需额外参数；如需旧行为加 `--no-batched`。
2. 告知用户当前进度（音频时长、批处理后约 2.3–2.6x 实时；干净短录音可达 ~5.8x），让用户知道在跑；
3. **模型选择（2026-09-02 A/B 实测定稿）**：medium（~2x 实时，准确率明显更高，默认）；base/small 已弃用为默认——噪音录音下乱码多；small（~6x 实时）保留作赶时间时的快速模式。模型均在本地目录 `C:/Users/ThinkPad/.workbuddy/models/faster-whisper-{base,small,medium}`，`WhisperModel()` 直接传目录路径；

### Step 3: 转录完成后提取要点

1. **转录是唯一必选项**（手记如有则合并补充，没有也能独立完成）；
2. **通读转录全文提取**，不要只 grep 关键词——grep 会漏掉分析逻辑和细节（2026-08-24 用户反馈：概括不全面）；
3. 转录质量校正：对照下方「常见名词校正表」结合上下文修正，表外拿不准的标注（待确认）；
4. 按 3 节结构归类：市场概要 → 基金经理操作与仓位 → 其他。

### Step 4: 提取核心要点（主题归位，宁全勿缺）

**核心原则：按主题/标的归位，不按会议顺序**——晨会讨论经常跳跃，同一标的会散落在录音 3-4 个位置，必须归拢合并（2026-09-02 用户反馈三点：逻辑归属错误、内容没合并归位、漏数据）。

**发言人结构（2026-09-02 用户提供）：**晨会固定三位——**运营主管**（开场/事务，归"三"）、**宏观分析师**（海外市场、利率、商品等宏观内容，归"一"）、**基金经理**（A股操作/仓位/个股，归"二"）。归属判断可做"发言人+主题"双重校验。

1. **动笔前先建"标的/主题清单"**：通读转录，列出所有被提到的资产和标的（美股/VIX、利率、黄金、原油、指数、个股…），再把转录全文按清单归拢，然后才开始写；
2. **内容分流规则（2026-09-02 定稿）**：三节结构——涉及**海外市场/大宗商品/宏观**的内容（含相关后市观点）归"一、市场概要"；**A 股盘面、基金经理的操作/仓位/个股/涉及 A 股的后市判断**归"二、基金经理操作与仓位"；闲聊归"三"；
3. **归属自检**：每个数据点问一句"这属于哪个资产/标的"——VIX 永远跟美股、商品各归各、A 股观点归二（2026-09-02 曾把 VIX 错放进黄金段落）；
4. **每个标的固定"数据 → 逻辑 → 动作"三段式**：数据（份额%、股息率、分红率、点位、日期）→ 逻辑链 → 操作动作；保留分析逻辑链不只留结论（❌"药明康德有 20 点空间" ✅"明年业绩上修则估值 16 倍→约 20 点空间"）；
5. **写完回扫**：每个标的写完后回扫转录一遍，把它被提到的所有具体数据列全——漏数据的根因是只取碰到的片段；
6. 听错的名词结合上下文修正（如"中兴国际"→中芯国际），拿不准的**在正文内标注（待确认）**。

### Step 5: 生成 docx（一次性脚本完成）

使用 `scripts/generate_morning_minutes.py` 生成。**不要**在生成后用 `doc_get_document_content` 反复验证样式——直接用 python-docx 写好就保存。

**实操模式（2026-09-03~09-09 定稿）**：把模板脚本复制到当日 workspace 为 `gen_minutes_MMDD.py`，只改标题日期和章节内容后运行；**不要**改 skill 目录里的模板。输出路径用当日 workspace 的绝对路径。

**函数签名坑（连续多日踩同一个 TypeError）**：`add_section_heading(doc, text)` / `add_sub_heading(doc, text)` —— 第一参数是 `doc`，漏传会报 `missing 1 required positional argument: 'text'`。

**样式规范：**

- 字体：**宋体**（中文）+ Times New Roman（英文/数字）；
- 页面：上下边距 1.6cm，左右 2.0cm；
- 单标题：`YYYY.MM.DD 会议纪要`，15pt 深蓝 `#1F3864`，居中粗体（**只一个标题，不要"会议纪要"+"日期"两遍**）；
- 节标题：12pt 深蓝粗体，段前 8pt、段后 3pt；
- 子标题：11pt 深蓝粗体，段前 5pt、段后 2pt；
- 正文：10pt 黑色，1.25 倍行距，段前 1pt、段后 1pt；
- 段落缩进：0.3cm 起始；
- **不加粗整段正文**——只对关键标签/标的加粗（如"光模块："、"洛阳钼业"），其余正常字重。

**结构模板（3 节固定，2026-09-02 用户定稿）：**

```
1. 一、市场概要：海外夜盘美股+VIX、宏观数据、全球利率与美联储、商品期货（黄金/金属/原油）、汇率与套息风险；
   后市观点中涉及海外/商品的内容也归这里
2. 二、基金经理操作与仓位（核心）：总仓位%、加减仓/清仓、交易计划、A股盘面与板块轮动、
   个股逻辑（数据→逻辑→动作）、涉及A股的后市判断
3. 三、其他/闲聊浓缩：技术讨论、工具交流一句带过
```

**段落合并规则：**同一子主题下的多条要点合并成 1 段，用分号/句号分隔，避免每个要点独占一行（节省版面）。同一标的散落在转录各处的内容必须合并到一处。

### Step 6: 交付

1. `present_files` 展示 docx；
2. 当日 memory 记一行：音频文件、纪要文件名；
3. 不必询问用户确认样式——按本 skill 默认即可。

## Efficiency Notes（重要）

- **转录提速（2026-09-03 A/B 实测定稿，模型不变）**：240s 切片、medium int8 beam=3 VAD 实测——baseline 159s（1.5x 实时）、cpu_threads=8 单独 149s（仅 ~6% 收益）、**cpu_threads=8 + BatchedInferencePipeline bs=8 → 102s（2.4x 实时，提速 ~36%），文本质量一致**。脚本已将批处理设为默认；**全程实测（2026-09-04~09-09）**：17–23 分钟录音 2.3–2.6x 实时（7.6–9.5 分钟），干净短录音可达 ~5.8x。CPU 瓶颈下 batch_size 再加大收益有限，勿盲目调参；
- **转录：beam=3**——beam=1 虽更快但数字/标的上错误率高，已弃用（2026-08-14）；
- **模型 A/B 结论（2026-09-02，19 分钟音频实测）**：base 乱码多已弃用；small 184s/6.1x 实时，噪音录音下名词错乱多；medium 540s/2.1x 实时，修正了 9/11 通胀数据日期、匈牙利工厂、券商/渝农商行、PCB 最硬、PTFE 板块、股息率 4-5%、原油涨利率涨等关键细节——**默认 medium**，赶时间可退 small；
- **Windows HF 缓存坑**：沙箱回收站机制会导致 HF 缓存 model.bin 损坏（报 "File model.bin is incomplete"）。规避：`HF_HUB_DISABLE_XET=1` + curl 直接下载模型文件到上述本地目录；**不要 `rm -rf` HF 缓存目录**（沙箱 safe-delete fail-closed 会中止整条命令）；
- **turbo 模型坑（2026-09-02 实测，勿再试）**：HF 社区的 faster-whisper-large-v3-turbo CT2 转换（deepdml / mobiuslabsgmbh / Infomaniak-AI 等）**全部是英文专用**——`is_multilingual: False` 烧录在 model.bin 元数据里，中文转录直接报 "English-only"/startoftranscript 错误，与 tokenizer 无关。要用 turbo 需自行 ct2 转换（需 torch+transformers，~30-40 分钟）或上 GPU。CPU 纯推理场景 medium int8 是性价比最优；
- **大文件下载（本机验证有效）**：HF 直连某些仓库只有 ~0.5MB/s 时，用 8 线程并行分块 curl（`-r start-end`）+ 断点续传补缺块 + cat 合并 + 字节数校验，1.6GB 约 5-8 分钟；下载后必须校验 total 字节数，缺块很常见；
- **失败快速暴露**：转录脚本 1-2 分钟内即报错——音量极低/无法识别语音时立即提示"重新录音或改用手记"，**绝不长时间空跑重试**；
- **不要读取截图**，除非用户明确说"参考截图内容"；
- **不要在生成后验证 docx**，直接交付；
- **不要重复写 memory**，每次只追加一行；
- **内容提取：先建主题清单归拢、写完回扫补数据**（2026-09-02 用户反馈定稿：按主题归位不按会议顺序、漏数据要靠回扫堵、宁全勿缺；不要只 grep 关键词）；
- 总目标：**15 分钟内完成**（medium 转录 5-9 分钟 + 处理 3-5 分钟；换 small 可压缩转录至 2-4 分钟，代价是错字增多）。
